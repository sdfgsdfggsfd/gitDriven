    From an idea to the game in an afternoon

    Nobody uploads plugins by hand. Approved code goes live on its own. Here's what that looks like on a normal day.

    1. 3:00 PM

      Someone in chat says they wish they could sit on stairs.

    2. 3:20 PM

      The wish becomes an issue. Someone picks it up, writes it (maybe with an AI agent) and tries it on a local server.

    3. 4:00 PM

      They open a pull request called “Add /sit on stairs”. GitHub builds it and the checks pass.

    4. 4:30 PM

      An approver reads how to test it and approves. It merges on its own.

    5. 4:31 PM

      The server notices the new commit, builds it and tells everyone online.

      Core » Update a1b2c3d ready (1 change(s)). Restart in ~10 min (unless another merge lands). See /changelog.

    6. 4:41 PM

      Ten minutes pass with no other merges. A one-minute countdown starts.

      Core » Server restarts in 60s.

    7. 4:42 PM

      The server is back. Everyone who joins sees the change, with who made it.

      Core » What's new in the last update:
      • Add /sit on stairs (#12) — alex

    8. 00:00 UTC

      The day's recap is published, listing every change and everyone who contributed.

    Restarts are batched

    After a merge the server waits ten minutes for more. Five merges in a row become one restart, and if nobody is online it updates right away.

    Broken builds never ship

    If a change doesn't build, the server keeps running the version it has and the admins get a notice.

    Undo is one click

    Didn't turn out well? Revert the pull request on GitHub and the server rolls back the same way it updated.

    Build something

    Anyone can add to the server. You don't need to be an experienced developer, and AI agents are welcome as long as a person reviews the result.

    1. 1

      Fork and clone

      You need Java 25 and git. Gradle downloads itself.

    2. 2

      Write your feature

      Small things go in plugins/playground/. Something bigger gets its own plugin in plugins/<name>/.

    3. 3

      Check it builds

      ./gradlew build collectServerPlugins
sh scripts/check-folia.sh
    4. 4

      Open the pull request

      Its title becomes the line players read in /changelog, so write it for them: “Add /sit on stairs”, not “refactor SitHandler”.

    5. 5

      Join and see it

      Once an approver says yes, the merge and the deploy happen on their own.

    It's Folia, not Paper

    Folia runs each region of the world on its own thread. There's no main thread, so Bukkit.getScheduler() doesn't exist here. Schedule on whatever owns the thing you touch:

    // An entity: its own scheduler
player.getScheduler().run(plugin,
    t -> player.setHealth(20), null);

// A block: its region's scheduler
Bukkit.getRegionScheduler()
    .execute(plugin, loc, () -> loc
        .getBlock().setType(Material.STONE));
